# KOICA AI 성과관리 (BUCAS PMC AI 사업비서) — v0.5

KOICA PMC 사업의 사업관리·성과관리를 하나의 지식베이스로 묶고, LLM이 근거와 함께 답하고(질의응답) 담당자에게 질문을 내는(점검 질문) 플랫폼의 출발점입니다.
전체 설계는 `docs/01_플랫폼_아웃라인.md`를 먼저 읽어 주세요.

## 빠른 시작

    pip install -r requirements.txt
    python scripts/init_db.py --reset     # 스키마 생성 + 시드 CSV 적재 + 문서 색인
    python scripts/check_alerts.py        # 규칙 점검 + AI 점검 질문 생성 (LLM 없이 동작)
    cp .env.example .env                  # ANTHROPIC_API_KEY 입력 → AI 사업비서 사용 가능
    streamlit run app/ui.py

## 회의록·후속조치 (v0.5)

[4. 사업관리 › 회의록·후속조치]가 **연도별 탭 + 행렬표**로 바뀌었습니다. 오른쪽 위 **[➕ 회의록 추가]**에서 대분류(과업 Activity)·중분류(내부/외부회의)·소분류(이해관계기관)와
안건·결과·후속조치를 입력하고 **저장하기 / Word로 다운받기 / PDF로 다운로드**할 수 있습니다. 표의 **[📄 Word]**를 누르면 그 회의록이 Word 파일로 내려받아집니다.
후속조치사항은 한 줄에 하나씩 `조치 내용 / 담당 / 기한` 으로 적으면 후속조치 목록(대쉬보드 기한 알림)에 자동 등록되고,
회의록은 `pmc/4_사업관리/문서/회의록/`에 검색용 문서로도 저장되어 AI 사업비서가 찾아 읽습니다. 자세한 내용은 `docs/04_회의록_후속조치_v0.5.md`.
연도 탭은 2026~2031년이 항상 보이고(`config/settings.yaml` weekly.years), 대분류·중분류·소분류로 걸러 볼 수 있습니다.

**주간업무보고**도 주차 × (PM·PAO·현지직원1~3·국내활동) 칸으로 바뀌었습니다. 칸을 누르면 간이 입력창(작성자·직책·활동내용)이 뜨고, 내용이 있는 칸은 초록색, 마지막 열 [📄 리포트]는 그 주차 보고서 미리보기와 Word·PDF 다운로드입니다.
주차는 '목요일이 속한 달' 기준(8월31일(월)~9월4일(금) = 9월 1주차)이며 첫 주와 칸 이름은 settings.yaml 의 `weekly` 항목에서 바꿉니다. 저장 파일: `pmc/4_사업관리/주간업무보고_주차별.csv`.

**[5. 성과관리 › 📊 성과점검표]**는 KOICA 성과관리양식 v3.2(`pmc/99. pre/2. PDM/성과관리양식_v3.2_final.xlsx`)의 '2. 성과점검표' 시트와 같은 배치입니다: 왼쪽 모니터링 매트릭스(지표명·정의·기초선·목표치·선정 근거·데이터 출처·측정 시기·수집 주체) + 오른쪽 연간 성과점검표(연간 실적치/목표치/달성률 × 1~7차년도, 누적 달성률, 비고). 오른쪽 아래 [✏️ 수정하기]에서 사업명·작성일, 지표 정의, 연간 목표치·실적치를 한 번에 고칩니다. 처음 실행할 때 지표·목표치가 양식 기준으로 한 번 갱신되고 이전 표는 `pmc/_백업`에 남습니다.

**[5. 성과관리 › 사업산출물]** 탭에는 `pmc/99. pre/2. PDM` 폴더의 내용이 모두 들어갔습니다: 사업산출물(6개) · 사업논리모형(PDM, '검증지표 추가제안' 열 포함) · 성과점검표(지표 + 연간 목표치) · 사업변화모델(트리) · 원문 파일.
각 표의 **오른쪽 아래 [✏️ 수정하기]**를 누르면 엑셀처럼 칸을 고치고 행을 추가할 수 있고, [💾 저장]하면 `pmc/5_성과관리/` CSV와 DB에 반영됩니다.
사업논리모형(PDM)은 **버전 관리**가 됩니다: v1은 RFP 첨부 원본이고, 오른쪽 위 **[➕ 새로운 버전 추가]**를 누르면 마지막 버전이 그대로 복사된 새 버전이 열려 바로 고칠 수 있습니다(상태 초안/검토중/확정, 변경 사유, 승인일 기록). 표 아래 **근거자료** 칸에 그 버전의 근거(회의록·공문 등)를 올려 두면 `pmc/5_성과관리/PDM근거/v{n}/`에 저장되고 AI 사업비서 검색에 포함됩니다. 표 아래 **[📗 Excel] [📄 Word] [📕 PDF]**로 그 버전을 PDM 양식 그대로 내려받을 수 있습니다(Excel에는 편집용 원본표·버전이력·근거자료 시트 포함). [5. 성과관리 › PDM 지표 (사업논리모형)] 탭도 같은 화면입니다.

왼쪽 위 로고는 `config/logo.png`(연세대학교 공식 시그니처, www.yonsei.ac.kr UI 페이지 파일)를 표시합니다. 다른 그림으로 바꾸려면 같은 이름으로 덮어쓰면 됩니다(.png/.jpg/.svg). 연세대 UI는 교육·행정 목적 사용만 허용되며 상업적 이용은 금지입니다.

처음 실행하면 기존 `회의록.csv`에 새 열이 자동으로 추가됩니다(이전 '회의유형'의 기관명은 소분류로 옮겨짐). 패키지 2개(python-docx, reportlab)가 추가되어 `AI_ME_v1.bat`이 첫 실행 때 설치합니다.

## 데이터 저장

화면에서 입력·수정한 내용은 `pmc/` 아래 **목차별 폴더**에 CSV·YAML·문서 파일로 저장됩니다(원본). `data/pmc.db`는 검색·집계용 캐시라 지워도 다시 만들어집니다.
폴더의 CSV를 엑셀로 고쳐도 자동 반영됩니다. 구조와 클라우드 연계 방법은 `docs/02_데이터저장_및_클라우드연계.md` 참고.

## 폴더 구성

    docs/                 플랫폼 아웃라인
    config/settings.yaml  모델명·알림 기준일·이상치 기준 등
    db/schema.sql         지식베이스(정형 데이터) 스키마
    pmc/                  목차별 데이터 저장 폴더(원본) — 첫 실행 때 자동 생성
    app/storage.py        파일↔DB 동기화(클라우드 전환 시 이 파일만 수정)
    data/seed/*.csv       초기 예시값 — [예시]/[입력필요]를 실제 값으로 교체 (엑셀에서 편집 가능)
    prompts/              시스템 프롬프트, 단계별 질문 은행
    app/rules.py          규칙 점검(기한·기초선 누락·이상치·후속조치)
    app/tools.py          LLM 도구(run_sql / search_documents / get_alerts)
    app/agent.py          모듈③ 질의응답 에이전트
    app/questioner.py     AI가 담당자에게 내는 점검 질문
    app/ui.py             Streamlit 화면
    app/minutes_doc.py    회의록·주간업무보고 Word·PDF·검색용 문서 생성
    app/weekly.py         주간업무보고 주차 계산·저장
    scripts/              DB 초기화, 문서 색인, 일일 점검

## 주의

- `data/seed`는 RFP·PDM 기준 자료입니다. 단, 계약체결일(2026-11-01)은 가정이고 담당 '(안)'은 제안값이며, 회의록·센터 실적은 [예시]입니다.
- 아직 로그인·권한통제·암호화가 없습니다. 실제 사업자료 적재 전에 추가가 필요합니다.
- 환자 식별정보는 넣지 않습니다(집계값만).
- 확인한 범위: DB 초기화, 규칙 점검, 질문 생성, 문서 검색, SQL 읽기전용 차단, 화면 5개 페이지 로딩. LLM 호출 구간(`agent.ask`, 질문 다듬기)은 API 키가 없어 실행 검증을 하지 못했습니다.
